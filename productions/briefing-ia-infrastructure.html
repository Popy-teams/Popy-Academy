Le principe qui ne change pas

Règle d'or POPY — non négociable L'IA ne mémorise pas les programmes dans ses poids. Elle s'appuie sur un référentiel officiel contrôlé (Éduscol / BO) + les contenus POPY validés. Le LLM reformule uniquement ce qu'on lui fournit — il n'invente jamais le programme.

Conséquence directe : on n'entraîne pas notre propre modèle. Ce qui compte, c'est la qualité du RAG (récupération dans notre base de connaissances) et du prompt de cadrage. Le LLM est interchangeable — c'est notre référentiel qui est la vraie valeur différenciante de POPY.

Phrase jury "POPY n'entraîne pas son IA sur Internet. Son moteur s'appuie sur un référentiel contrôlé issu des programmes officiels, enrichi de contenus validés. L'IA reformule et accompagne dans les limites de ce référentiel."

Comment ça marche — les blocs

L'architecture se décompose en deux couches indépendantes. Le RAG (Retrieval-Augmented Generation) est responsable de la recherche : il convertit la question en vecteur d'embedding et récupère par similarité les chunks les plus pertinents du référentiel officiel. Le LLM reçoit ensuite ces chunks comme contexte et génère une réponse en se limitant strictement à ce qu'il a reçu. La qualité de la réponse dépend donc d'abord de la qualité du référentiel et de la recherche — le modèle lui-même est secondaire et interchangeable.

Séquence exacte à chaque requête :

Étape 1
Question enfant
L'enfant pose sa question via le front React.
Étape 2
Recherche RAG
On cherche dans PostgreSQL+pgvector les 3–5 chunks les plus proches du programme officiel.
Étape 3
Construction prompt
On assemble : profil enfant + chunks trouvés + question. Minimisé, pas de données brutes.
Étape 4 — choix
Appel LLM
C'est ici qu'on choisit entre Option A (API Mistral EU) et Option B (self-hosted). Le reste du code ne change pas.
Étape 5
Réponse sourcée
L'enfant reçoit la réponse avec les sources citées ("D'après le programme CM1 — Fractions").
Si le RAG ne trouve rien Le moteur retourne un refus contrôlé ("Je ne trouve pas ça dans le programme") plutôt que de laisser le LLM inventer. C'est une règle de code, pas une convention.

Options retenues pour le site

Option A — API cloud EU
Court terme · démarrage immédiat
On appelle un LLM via API chez un fournisseur européen. Le modèle tourne chez eux, on envoie le prompt et on reçoit la réponse. Zéro GPU à gérer, zéro maintenance modèle.
Démarrage en heures Maintenance nulle Coût variable Données chez tiers EU
Option B — Self-hosted GPU EU
Moyen terme · montée en charge
On loue un serveur GPU en Europe (Scaleway, OVH) et on y déploie un modèle open source via Ollama ou vLLM. Le code Fastify appelle notre propre endpoint — techniquement identique à l'option A.
Données ne sortent pas Coût fixe prévisible ~280 €/mois fixes Maintenance serveur
Pourquoi les deux options sont compatibles Le code Fastify appellera une interface abstraite LlmClient. Derrière, une variable d'environnement pointe soit vers api.mistral.ai soit vers ton-serveur-gpu.popy.fr. On peut basculer sans réécrire le moindre code.
Ce qu'on ne fait pas On n'entraîne pas de modèle from scratch (millions d'exemples, budget MLOps hors portée) et on ne fine-tune pas maintenant (à réévaluer après 6 semaines de test si le prompt seul ne suffit pas). OpenAI est écarté en priorité car les données transiteraient hors EU — une analyse de transfert et un DPA spécifique seraient nécessaires (Yacine).

Pour l'Option B — modèles self-hosted (GPU EU)

Ces modèles sont open source, libres à déployer. On les fait tourner avec Ollama (simple) ou vLLM (plus performant à forte charge) sur le serveur GPU. Critères POPY : qualité du français, instruction-following strict, refus des hallucinations hors contexte.

Mistral 7B Instruct
Open source · ~4 GB VRAM (Q4)
Valeur sûre. Excellent français, très bon pour rester dans le contexte fourni. Tourne confortablement sur A10 GPU. C'est le choix de référence pour démarrer.
Recommandé20-40 tok/s sur A10
LLaMA 3.1 8B Instruct
Meta · Open source · ~5 GB VRAM (Q4)
Légèrement plus capable que Mistral 7B sur la compréhension de contexte. Même gabarit, même coût. Les deux sont interchangeables — choisir selon les tests.
Recommandé18-35 tok/s sur A10
Phi-3.5 mini 3.8B
Microsoft · Open source · ~2.5 GB VRAM
Surprenant pour sa taille. Excellent instruction-following, tourne vite. Qualité en français légèrement en dessous des 7-8B. Idéal si on veut réduire les coûts GPU ou pour le robot.
GPU modeste suffisant
Mixtral 8x7B
Mistral AI · Open source · ~26 GB VRAM
Nettement au-dessus en qualité. Architecture mixture-of-experts : se comporte comme un 12B tout en étant plus efficace. Mais nécessite un GPU A10 dédié avec beaucoup de VRAM. À envisager si les 7B montrent des limites.
GPU A10 24GB minimum
Ce qui compte vraiment pour évaluer un modèle sur POPY Les benchmarks généraux sont trompeurs pour notre usage. Ce qu'on teste en pratique : (1) le modèle reste-t-il dans les chunks fournis sans inventer ? (2) son français est-il naturel et adapté à l'âge ? (3) dit-il "je ne sais pas" quand le RAG ne trouve rien ?

Contraintes RGPD sur la couche IA

POPY traite des données d'enfants. Le plan RGPD de l'équipe (Yacine) pose des règles directes sur le choix du LLM. Ce n'est pas qu'une préférence — c'est une contrainte projet figée.

Option LLMStatut RGPDCe que Yacine doit faire
Mistral API (EU) Chemin court Signer le DPA standard Mistral. Clause de non-entraînement sur nos données. Simple.
Self-hosted GPU EU Aucun sous-traitant IA Rien sur le LLM lui-même — les données ne sortent pas. DPA uniquement pour l'hébergeur.
Scaleway Inference Faisable DPA Scaleway (hébergeur UE). Vérifier clause modèle.
OpenAI (US) Complexe Analyse de transfert hors UE + fiche spécifique. Possible mais couche juridique lourde.

Deux règles techniques figées, quoi qu'on choisisse :

  • Le prompt envoyé au LLM doit être minimisé — pas de données personnelles brutes de l'enfant dans le contexte, uniquement le niveau scolaire et les chunks RAG.
  • Pas de log des prompts côté serveur LLM sur le long terme — si on loggue pour debug, TTL court et accès restreint (Fabio).

Phase P4 — semaines 7-8
Moteur RAG fonctionnel, sans LLM
Service retrieveOfficial() + buildGroundedPrompt(). Endpoint POST /pedagogy/ask en mode stub (réponse template). Tests E2E refus hors référentiel.
Phase P5 — semaines 9-10
Branchement LLM (Option A d'abord)
Interface LlmClient abstraite. Mistral API EU derrière PEDAGOGY_LLM_ENABLED=true. System prompt verrouillé. Migration Option B sans réécriture.
Phase P6 — semaines 11-12
Intégration frontend + démo jury
"Parler à Popy" branché sur /pedagogy/ask. Sources affichées dans l'UI. Fallback hors ligne (IndexedDB).

AGX Orin 32GB — recommandé pour notre cas d'usage Même puce que le 64GB (2 048 cœurs CUDA, puissance de calcul identique), moitié moins de RAM. Pour Mistral 7B Q4 ou LLaMA 3.1 8B Q4 (~4–5 GB VRAM), les performances sont strictement identiques. La 64GB n'apporte rien de plus tant qu'on reste sur du 7B — la seule raison d'y passer serait de vouloir faire tourner un modèle 14B à terme.
Orin NX 16GB — dégradation perceptible La puce passe à 1 024 cœurs CUDA (moitié moins). Le débit tombe à 4–6 tokens/seconde : les réponses arriveront par à-coups plutôt qu'en continu, ce qui se sent clairement dans une conversation avec un enfant. Le modèle 7B tient en RAM mais avec peu de marge pour les autres processus (STT, TTS, vision). Option envisageable pour un prototype de démonstration — pas pour un produit final.

Résumé des décisions

Entraîner notre propre modèle ?
Non. Hors portée et inutile avec l'architecture RAG. Notre valeur est dans le référentiel, pas dans le modèle.
Fine-tuner un modèle existant ?
Pas maintenant. À réévaluer après 6 semaines de test si le prompt ne suffit pas à tenir le registre pédagogique.
Option LLM site — court terme
Option A : Mistral API EU (Mistral Small). Démarrage immédiat, ~40€/mois au lancement, RGPD simple.
Option LLM site — montée en charge
Option B : Self-hosted GPU EU (Scaleway/OVH). ~280€/mois fixes. Coût stable, données ne sortent pas. Bascule à ~800 utilisateurs actifs/jour.
Modèle self-hosted recommandé
Mistral 7B Instruct ou LLaMA 3.1 8B Instruct — les deux sont équivalents, tester les deux et retenir le meilleur sur le français pédagogique.
Hébergement
EU obligatoire. Scaleway ou OVH en premier choix. VPS + Docker Compose + Caddy. Pas de Kubernetes avant juin 2027.
Robot — hardware
Jetson AGX Orin 32GB (~650€ module, ~1 500–1 800€ prototype complet). Performances identiques au 64GB sur les modèles 7B. La 64GB n'est pertinente qu'en cas de montée vers un modèle 14B.
Robot — modèle IA
Mistral 7B Q4 ou LLaMA 3.1 8B Q4 pour commencer. Upgrade possible vers Phi-3 medium 14B Q4 si la qualité doit monter.
Ce qu'on peut annoncer avec certitude L'architecture POPY (RAG + LLM reformulateur + référentiel officiel) est solide, faisable avec la stack en place, conforme RGPD avec Mistral EU, et scalable à coût raisonnable. La production du site peut démarrer maintenant — le robot suit la même architecture, plus tard.
